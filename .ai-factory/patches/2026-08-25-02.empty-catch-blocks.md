# Patch: Empty Catch Blocks Swallowing Errors

**Date:** 2026-08-25
**Severity:** HIGH
**Tags:** #error-handling #react #silent-fail #debugging
**Files:** 44 React components (112 instances)

## Problem
112 empty `catch {}` blocks across 44 React components silently swallowed all errors. No logging, no user feedback, no toast. Errors were invisible — bugs appeared as "nothing happens" instead of actionable errors.

## Root Cause
Boilerplate try/catch added during initial scaffolding without deciding what to do on error. The `catch {}` pattern was copy-pasted across components.

## Prevention
- **aif-implement:** NEVER write `catch {}` or `catch (e) {}`. At minimum, add `console.error('ComponentName:', e)` or `toast.error('Action failed')`. For API calls, show user-facing error feedback.
- **aif-review:** Grep for `catch\s*\{\s*\}` and `catch\s*\([^)]*\)\s*\{\s*\}` — flag every empty catch as a finding.
- **aif-fix:** When fixing silent failures, add both logging (for debugging) and user-facing feedback (toast/alert).

## Evidence
- Commit `4e8a11e` — fixed 112 empty catch blocks across 44 components
- Pattern: `try { await fetch(...) } catch {}` → should be `catch (e) { console.error(...); toast.error(...) }`
