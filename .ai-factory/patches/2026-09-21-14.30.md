# Documentation Drift Fix — Stale Counts

**Date:** 2026-09-21 14:30
**Files:** CONTEXT.md, README.md, orbit/__init__.py, orbit/orbit/__init__.py
**Severity:** low

## Problem

Verification audit found 6 documentation counts were stale and didn't match reality:

1. "438 modules" → actual 490 Python files in core/
2. "180 blueprints" → actual 188 blueprint files
3. "83 React components" → actual 138 JSX files
4. "25 agents" → actual 26 entries in AGENT_REGISTRY
5. "90.3% ground-truth accuracy vs 103 items" → actual 85% on 20 items
6. "22 agents, 19 tools" in package docstrings → actual 26/24

## Root Cause

Documentation was written at earlier points in development and never updated when new agents/tools/systems were added. The ground-truth claim was particularly misleading — it referenced a 103-item eval that was superseded by a 20-item eval with different accuracy.

## Solution

Updated all stale counts to match actual file system reality:
- CONTEXT.md: 490 modules, 188 blueprints, 138 components
- README.md: 85% accuracy on 20 items, 26 agents
- orbit/__init__.py: 26 agents, 24 tools, 490 modules, 138 components
- orbit/orbit/__init__.py: 26 agents, 24 tools, 490 modules, 188 blueprints

## Prevention

- After adding new agents, tools, or systems, update documentation counts immediately
- Run a verification script that counts actual files and compares to documented counts
- Consider adding a CI check that flags documentation drift
