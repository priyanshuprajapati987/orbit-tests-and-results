# Patch: Bare except: pass in Python — Silent Error Swallowing

**Date:** 2026-08-23
**Severity:** HIGH
**Tags:** #python #error-handling #logging #debugging
**Files:** chat_api.py, LLM router (20+ locations)

## Problem
20+ `except Exception: pass` blocks in Python code swallowed errors silently. When smart_router, task_continuity, proactive_context, or smart_memory failed, the error was invisible — no log, no traceback. Debugging was impossible.

## Root Cause
Boilerplate try/except added during feature integration without deciding on error handling strategy. The `pass` pattern was copy-pasted.

## Prevention
- **aif-implement:** NEVER write `except Exception: pass` in Python. At minimum use `except Exception as exc: logger.debug("Component failed: %s", exc)`. For user-facing features, use `logger.warning()` or `logger.exception()`.
- **aif-review:** Grep for `except.*:\s*pass` in Python files — flag every instance.
- **aif-fix:** Replace bare `pass` with at least `logger.debug()`. Use `logger.exception()` for unexpected errors, `logger.debug()` for expected fallbacks.

## Evidence
- Commit `ab68816` — replaced 20+ `except Exception: pass` with `except Exception as exc: logger.debug(...)` in chat_api.py and LLM router
