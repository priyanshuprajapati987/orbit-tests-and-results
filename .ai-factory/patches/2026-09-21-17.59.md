### React: WebGL Performance Bug (CRITICAL)

**File: `ui_provided/src/components/ThreeDOrbitCore.jsx`**

**Bug:** `useEffect` on line 70 had `[currentMode, autoRotate, rotationSpeed, activeAgentId, isSpeaking, isListening, isThinking, onSelectAgent]` as dependencies. Every time ANY of these changed (e.g., switching visualization mode, toggling auto-rotate), the entire Three.js scene (6000+ objects: 1200 particles, 2000 galaxy stars, 3000 vortex particles, 36 audio bars, 22 agent nodes, 3 rings, wave mesh, grid) was destroyed and rebuilt from scratch.

**Fix:** 
- Added refs for all changing values (`autoRotateRef`, `rotationSpeedRef`, `currentModeRef`, `isSpeakingRef`, `isListeningRef`, `isThinkingRef`, `activeAgentIdRef`, `onSelectAgentRef`)
- Added sync effects (`useEffect(() => { ref.current = value }, [value])`) to keep refs current
- Animation loop now reads from refs instead of closure variables
- `useEffect` dependency array reduced to `[]` (mount/unmount only)
- Scene is created ONCE and reused for the component's lifetime

### React: Stale Closure Keyboard Handler

**File: `ui_provided/src/App.jsx`**

**Bug:** The `useEffect` for keyboard shortcuts (Escape key) had `[cmdOpen, historyOpen, notifOpen, activePanel, closePanel]` as dependencies. Every time any panel opened/closed, the entire keydown listener was removed and re-added to `window`.

**Fix:**
- Added refs: `cmdOpenRef`, `historyOpenRef`, `notifOpenRef`, `activePanelRef`
- Added sync effects to keep refs current
- Escape handler now reads from refs instead of captured state
- Effect dependency array reduced to `[]` (register once)

**Also fixed:** `orbit-suggestion` event handler `setTimeout` now checks `aliveRef.current` before calling `sendMessageRef.current` (prevents stale callback after unmount).

### React: AudioContext Memory Leak

**File: `ui_provided/src/components/ChatInput.jsx`**

**Bug:** `captureRawWav()` created an `AudioContext` (line 118) and called `audioCtx.close()` (line 137). If any error occurred between those lines (e.g., in `setTimeout`, `processor.disconnect()`, `resampleBuffer()`), the `close()` was never called → AudioContext leaked.

**Fix:** Wrapped the entire function body in `try/finally` to guarantee `audioCtx.close()` is always called, even on exceptions.

## Lessons Learned

1. **Flask error handling:** Use `@json_error_handler` consistently across ALL blueprints. HTML 500 pages leak implementation details. The decorator pattern is low-friction (one line per route).

2. **Three.js + React:** NEVER put scene-rebuilding code in a `useEffect` with changing dependencies. Store scene state in refs. The animation loop should read from refs, not closures. React's re-render cycle and Three.js's animation loop are fundamentally different timing models.

3. **Keyboard shortcuts:** State-dependent `addEventListener` effects cause unnecessary churn. Use refs for values that the handler needs but shouldn't trigger re-registration.

4. **AudioContext cleanup:** Always use `try/finally` around AudioContext/WebRTC resources. These are OS-level resources that leak if not explicitly released.
