# Patch: Flask Blueprint Endpoints Missing Error Handling

**Date:** 2026-08-25
**Severity:** HIGH
**Tags:** #python #flask #error-handling #api #500-errors
**Files:** voice_bp.py (9 endpoints)

## Problem
All 9 voice blueprint endpoints had no try/except. Any exception (missing config, unavailable TTS engine, bad JSON) returned a raw 500 with stack trace to the client.

Additionally, `request.get_json(force=True)` without `silent=True` returned 400 on non-JSON bodies instead of gracefully handling.

## Root Cause
Blueprint endpoints were written as "happy path only" — no defensive error handling. The `get_json(force=True)` without `silent=True` is a Flask anti-pattern.

## Prevention
- **aif-implement:** Every Flask endpoint MUST have: (1) try/except wrapping the entire body, (2) `get_json(silent=True) or {}` instead of `get_json(force=True)`, (3) `logger.exception()` on catch, (4) structured JSON error response with 500 status.
- **aif-review:** Check every `@blueprint.route` handler for try/except. Check every `get_json()` call for `silent=True`.
- **aif-fix:** When adding new blueprint endpoints, always use this template:
  ```python
  @bp.route("/api/endpoint")
  def endpoint():
      try:
          data = request.get_json(silent=True) or {}
          # ... logic ...
          return jsonify(result)
      except Exception as e:
          logger.exception("endpoint failed")
          return jsonify({"error": "description"}), 500
  ```
