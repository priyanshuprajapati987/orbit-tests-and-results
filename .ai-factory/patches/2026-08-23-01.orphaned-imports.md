# Patch: Orphaned Blueprint Imports from Deleted Modules

**Date:** 2026-08-23
**Severity:** CRITICAL
**Tags:** #python #import #crash #blueprint #server-startup
**Files:** ambient_bp.py, lab_bp.py, config.py

## Problem
Flask blueprints (`ambient_bp`, `lab_bp`) imported modules that had been deleted (`fused_senses`, `sim_lab`). When server.py tried to import these blueprints, it crashed with ImportError, preventing the entire Flask app from starting.

Additionally, `config.py` imported `from .pform import get_platform` but `pform.py` had been deleted.

## Root Cause
Modules were deleted as part of cleanup but their import references in blueprints and config were not removed. The import chain: server.py → blueprint → deleted module = crash.

## Prevention
- **aif-implement:** When deleting a module, search for ALL import references across the codebase before committing. Use `grep -r "from.*deleted_module"` pattern.
- **aif-review:** After any module deletion, verify no other file imports from it. Check blueprint registrations in server.py.
- **aif-fix:** When removing a module, also remove or update: (1) all import statements referencing it, (2) all blueprint registrations, (3) all config references.

- Commit `7def623` — deleted ambient_bp.py, lab_bp.py, removed pform import from config.py
