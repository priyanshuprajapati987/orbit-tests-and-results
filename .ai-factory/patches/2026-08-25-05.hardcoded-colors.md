# Patch: Hardcoded Colors Breaking Light Mode

**Date:** 2026-08-25
**Severity:** MEDIUM
**Tags:** #react #theming #css #design-system
**Files:** LearnedRouterPanel.jsx, MCPPanel.jsx, SmartBrowserPanel.jsx, AppHeader.jsx

## Problem
3 panels used hardcoded dark background colors (`rgba(18, 16, 29, 0.72)`, `#0d0b1a`, etc.) instead of theme CSS variables. In light mode these panels stayed dark, breaking the theme.

## Root Cause
Panels were developed in dark mode only and colors were hardcoded inline instead of using the design system's CSS custom properties (`var(--orbit-bg)`, `var(--orbit-surface)`, etc.).

## Prevention
- **aif-implement:** NEVER use hardcoded color values in inline styles. Always use `var(--orbit-*)` CSS custom properties. The theme tokens are: `--orbit-bg`, `--orbit-surface`, `--orbit-surface-hover`, `--orbit-border`, `--orbit-text`, `--orbit-text-secondary`, `--orbit-header-bg`.
- **aif-review:** Search for hardcoded color values (`#[0-9a-f]{3,8}`, `rgb(`, `rgba(`) in inline styles of React components. Flag any that aren't using CSS variables.
- **aif-fix:** Replace hardcoded colors with the corresponding CSS variable from the design system.

## Evidence
- Commit `9b32309` — converted 3 panels from hardcoded dark colors to theme tokens
- Commit `0e9e015` — fixed AppHeader hardcoded `rgba(18, 16, 29, 0.72)` → `var(--orbit-header-bg)`
